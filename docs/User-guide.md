# User guide

## Start a flight

Build and run from the instructions in the README. The menu presents Start Mission, High Scores, How to Play, Controls and Exit. Use Up/Down or W/S and Enter. Controls are shown on the start screen and explained in a separate screen.

Move with WASD or arrow keys. Hold Space for continuous fire. Stay inside the space below the top status bar. White scouts travel straight, orange weavers move vertically while patrolling, and purple hunters aim toward your position before a fast charge. Move after a hunter commits its charge to evade it.

You start with three lives. A collision removes one life and grants a brief period of protection. Survive the sector countdown to advance. The three sectors last 30, 35 and 40 seconds; enemy speed and density increase. Finishing the final countdown completes the mission. Esc abandons the active run and returns to the menu without recording that unfinished run.

| Pickup | Effect |
| --- | --- |
| Cyan R | Rapid fire for six seconds |
| Purple S | Shield for six seconds |
| Green + | Recover one lost life, up to the starting maximum |

Pickups appear every eight seconds and cycle through the three effects. The HUD displays the remaining rapid-fire and shield time. P pauses/resumes the simulation; M mutes/unmutes audio; F3 toggles diagnostic boxes and timings. Choose Exit in the menu or close the window to leave.

## Record a score

At defeat or victory, type an alphanumeric pilot name up to twelve characters, then press Enter. A blank name records as PILOT. The screen reports success or a save error. After a successful save, R retries, H opens the table and Esc returns to the menu. Esc before saving attempts to save first. Only the highest ten entries are retained.

Scores are stored as JSON under `%LOCALAPPDATA%/SideScrollerShooter/highscores.json`. Do not edit this file while the game is saving. A developer can select a separate directory with `SIDESCROLLERSHOOTER_DATA`. The graphics test automatically uses its own directory and cannot populate the normal leaderboard.

## Tune the world

Edit `Config/world.json`, then rebuild so the updated file is copied beside the executable. Change `playerX`, `playerY`, `playerSpeed`, `lives`, `bulletSpeed`, `powerUpInterval`, `powerUpDuration`, and `invulnerabilitySeconds` for player rules. Configure each sector using `duration`, `spawnInterval`, `enemySpeed`, `pattern` and `initialEnemies` coordinates/types.

Enemy types are `scout`, `weaver` and `hunter`. Initial enemy X coordinates must lie between half the viewport width and width+200, and Y coordinates between 160 and height-60. Player X lies between 60 and width-60; player Y lies between 160 and height-60. Viewports support 1120–1920 by 720–1080. Spawn intervals must be at least 0.25 seconds and enemy speeds no more than 450. These constraints keep the current layout and discrete collision system within its intended range.

Invalid settings stop startup with an explicit configuration exception rather than silently substituting an unexplained world. Restore the supplied JSON if startup fails after an edit.

## Checks and troubleshooting

A missing asset error means the content pipeline or copied output is incomplete; rebuild from the solution with all source assets present. A font error may indicate Arial is unavailable. A NuGet NU1900 warning means the vulnerability service could not be reached; it is not a C# compilation error. Restore again with network access to obtain the check. No silent suppression of that warning is configured.

The performance overlay shows recent CPU timings rather than an FPS promise. AABBs intentionally include some transparent sprite corners. Cross-platform runtime behaviour, sound balance on different speakers and human campaign balance are not yet comprehensively verified.
